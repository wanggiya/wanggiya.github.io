# S2 grids and nearest-stop areas — 2026-10-19

This update builds on the H3 version. It adds a fixed-level S2 grid and an independent Thiessen/Voronoi stop-area overlay. The four metric grids, H3, heatmap colors, automatic vehicle analysis, vehicle smoothing, bankruptcy page, public Worker URL, and architecture note are retained.

## Install

Unzip into a temporary folder. Keep your existing repository and its `.git` directory.

**Option A: apply the included Git patch**, if your files still match the previous H3 ZIP:

```bash
cd /path/to/your/existing/project
git status --short
git apply --check /path/to/extracted/S2_Voronoi_Update.patch
git apply /path/to/extracted/S2_Voronoi_Update.patch
git diff --check
git diff --stat
```

The patch check verifies applicability without editing files. If it fails, do not force it; compare/copy the changed files below and preserve any edits you made since the H3 update. The patch does not commit or push, and new files remain untracked until you stage them. It is based on the H3 version; it is not intended for older pre-H3 versions.

## S2 controls

Open **Interactions → Draw grid / choose area → Grid type → S2 quadrilateral index**. Start at **level 13**. Higher levels make smaller cells; the UI supports 8–18. Every generated cell uses the selected level, rather than a mixed-size covering.

Choose current view, a drawn rectangle/polygon, or visible-network coverage. Click **Draw grid**. The heatmap, color ramps, line appearance, weights, cell inspection and auto-update vehicle analysis work as before. Click Draw grid to apply changed grid settings; Recalculate keeps the existing grid (network scope regenerates occupied coverage).

S2 has variable cell areas and edge lengths. Whole-cell density uses the cell's spherical area from `Cell.exactArea()` multiplied by the mean Earth radius squared. Clipped fragments use their geographic polygon area. The S2 token remains attached to a clipped fragment, but the fragment is no longer the whole S2 cell. Tokens are strings; 64-bit cell IDs are never converted to ordinary JavaScript numbers.

Coverage is generated by bounded traversal of the S2 hierarchy with rectangular rejection, then polygon intersection. Cell edges are sampled along their great circles for display/clipping. The shared analyzer still measures route lengths and tests polygon containment in regional local ENU meters, so these are regional approximations. Analysis is limited to 250 km around Boston and 5,000 candidate cells, with a conservative area preflight. Oversized work fails with a message rather than silently omitting cells.

## Thiessen / Voronoi controls

Open **Interactions → Nearest-stop areas**:

1. Enable the stop layers and routes you want to analyze in the main layer panel.
2. Choose **Group by MBTA parent station** or **Individual stops**.
3. Choose current view or draw a rectangle/polygon.
4. Click **Calculate stop areas**.
5. Click a region to inspect its site, area, and member-stop count.

Use **Show stop areas** to hide/show the result. Under **Stop-area appearance**, change the RGB/picker color and fill opacity. **Clear stop areas** removes only this overlay. The S2/H3/metric grid remains independent; hide either overlay when comparing them visually.

The grid and stop-area tools share the same drawn selection. Changing it does not redraw existing results automatically. Clearing the grid also clears the shared selection, but does not remove an already calculated stop-area result. Select Current map view or draw again before the next drawn-area calculation.

Station grouping uses the MBTA `parent_station` relationship already present in loaded stop data. The representative position is the mean of that station's currently shown stop coordinates. It is not a fetched station entrance or an official centroid. Stops without parent metadata stay individual. Co-located representatives are merged into one geometric region while retaining their member IDs. Changing selected routes/platforms can change a station representative, so recalculate after changes.

All currently shown stops participate in the calculation, including those outside the selected area. Only the output is clipped to the selected boundary. This prevents the viewport edge from artificially eliminating a nearby competing stop. The result describes the nearest selected site, not the nearest stop in the entire MBTA system if some routes/stops are hidden or not loaded. The status shows route-loading progress for that reason.

Calculation uses local ENU meters, not longitude/latitude degrees. It runs in a worker and has limits of 10,000 input stops and 5,000 output regions. Results are manual snapshots: moving vehicles do not trigger recalculation of stop regions. No extra MBTA requests are added. Voronoi has its own worker and overlay, so it can run independently of grid analysis.

**Interpretation:** these are nearest-by-straight-line-distance regions. They do not model sidewalks, station entrances, rivers, bridges, travel time, service frequency, or actual transit connections. Grouped-station regions are nearest to their representative points. Delaunay triangle edges are a separate analysis concept; this release implements the recommended S2 and Voronoi pair.

## Validation

From the project folder, with a recent Node.js version:

```bash
node tests/s2-voronoi.test.mjs
node tests/h3-grid.test.mjs
node tests/grid-analysis.test.mjs
node tests/color-auto.test.mjs
```

Passed:

- S2 fixed levels, string-token round trips, spherical areas, point counts, route analysis, clipped-area conservation, stable IDs, network union, size and region guards.
- Voronoi meter-based bisectors, conserved area, outside-area competitors, single/co-located/collinear sites, station grouping, missing-parent fallback, polygon holes, empty input and size guards.
- Existing H3 tests, 12 metric-analysis suites, and color/auto-scheduler tests.
- Chromium checks with controlled MBTA fixtures: S2 worker/controls/heatmap/clipping/network scope, Voronoi station and stop modes, region inspection, visibility, a real mouse-drawn rectangle, clearing, H3/metric fallback, custom colors and automatic analysis without extra API calls or camera movement, dark/mobile layout, and no JavaScript errors.

Browser checks use fixture MBTA responses and do not validate the live upstream feed, production Worker, or live basemap delivery. The package.json remains unchanged; Node may print an ESM module-type warning, which does not indicate a test failure.
